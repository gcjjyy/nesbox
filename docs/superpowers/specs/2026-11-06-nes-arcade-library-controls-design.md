# NESBOX NES·아케이드 라이브러리 및 코어별 조작 설계

## 의도

NESBOX의 현재 NES 라이브러리를 보존하면서 `dosgamebox_archive`의 NES 및
아케이드 자산을 가져오고, 사용자가 하나의 라이브러리에서 시스템별로 찾고
플레이할 수 있게 한다. NES는 현재 FCEUX 실행 경로를 유지하고, 아케이드는
EmulatorJS의 MAME 2003-Plus와 FBNeo 코어를 사용한다. 시작 안내와 설정은
시스템별 키 구성을 같은 데이터에서 보여 주고 편집하게 한다.

작업은 사용자 요청 순서대로 진행한다.

1. NES 추가
2. MAME/FBNeo 아케이드 추가
3. ALL/NES/MAME 필터와 필터 범위 내 검색
4. 시작 가이드의 코어별 키 탭
5. 설정의 코어별 키 커스터마이징

## 현재 상태와 확인된 자산

- 운영 데이터 경로는 `/home/gcjjyy/lab/nesbox-data`이고, 현재 NES 게임은
  110개다.
- 아카이브 NES는 ZIP 33개이며 모두 ZIP 무결성, 단일 `.nes` 엔트리 및 iNES
  헤더 검사를 통과했다.
- 그중 현재 라이브러리와 ROM 전체 바이트 및 PRG/CHR 데이터가 같은 항목은
  5개다.
- 같은 작품이지만 지역판·번역판·리비전이 다른 것으로 판단되는 항목은
  7개이며, 나머지 21개는 현재 라이브러리에 없는 작품이다.
- 아카이브 아케이드는 `mame` 239개와 `fbn` 83개, 총 322개다. 모든 ZIP이
  무결성 검사를 통과했고 모든 항목에 카탈로그 이미지와 컨트롤러 메타데이터가
  연결되어 있다.
- 과거 앱 분석 결과 `mame`은 `mame2003-plus`, `fbn`은 `fbneo`를 사용했다.
- 현재 앱에는 FCEUX만 활성화되어 있고, 키보드·게임패드·터치 입력은 NES의
  방향키, A/B, Select, Start에 맞춰 고정되어 있다.

## 목표

- 현재 라이브러리의 제목, 커버, 고정 상태, 최근 플레이 및 브라우저 저장
  상태를 보존한다.
- 가져오기를 재실행해도 같은 게임이나 파일이 중복 등록되지 않게 한다.
- 정확히 같은 NES ROM 5개는 건너뛴다.
- 같은 작품의 다른 ROM 7개는 별도 판본으로 보존하고 제목에서 구분한다.
- MAME 2003-Plus와 FBNeo는 내부적으로 별개 프로필로 유지하지만 UI에서는
  모두 `MAME` 카테고리로 표시한다.
- 카테고리 선택 후 검색하면 그 카테고리 안에서만 결과가 나온다.
- NES와 MAME의 기본 키를 시작 안내, 도움말, 설정에서 일관되게 보여 준다.
- MAME은 1인 플레이 기준 방향, Coin, Start, 6개 액션 버튼을 제공한다.
- 사용자 키 설정은 브라우저에 저장되고 기존 사용자 설정과 호환된다.
- ROM과 스크린샷은 Git에 추가하지 않고 운영 데이터 디렉터리에 둔다.

## 비목표

- 이번 범위에서는 SNES 코어를 활성화하지 않는다.
- MAME의 2~4인 동시 플레이용 별도 키 구성은 제공하지 않는다.
- 라이트건, 트랙볼, 스티어링 휠, 페달 등 특수 입력의 정밀 매핑은 제공하지
  않는다. 코어의 디지털 대체 입력이 있으면 사용할 수 있지만 별도 UI는 만들지
  않는다.
- ROM, 스크린샷 또는 BIOS의 공개 배포 권리를 보증하지 않는다. 운영 자산은
  현재와 같이 비공개 데이터 경로에 유지한다.
- 모든 322개 게임의 완전 자동 플레이 판정은 하지 않는다. 대표 게임 검증과
  전체 카탈로그·파일 무결성 검증을 분리한다.

## 채택한 접근

### 채택: EmulatorJS를 아케이드 전용 런타임으로 통합

EmulatorJS 및 코어 패키지의 검증된 버전을 정확히 고정한다. `latest` CDN을
런타임에 참조하지 않고 설치된 패키지의 배포 자산을 앱의 정적 코어 디렉터리로
복사한다. MAME 게임에는 MAME 2003-Plus를, FBN 게임에는 FBNeo를 명시적으로
선택한다. 선택을 확장자나 브라우저의 마지막 코어 설정에 맡기지 않는다.

EmulatorJS 접근은 아카이브가 원래 목표로 했던 코어와 일치하고, ZIP 로딩,
영상·오디오, 상태 저장 및 6버튼 입력을 이미 제공한다. NESBOX는 버전 종속
코드를 하나의 `NesboxCore` 어댑터에 가두고, 나머지 React UI와 저장 코드는
기존 코어 계약만 사용한다.

EmulatorJS가 자체 캔버스를 생성하므로 코어 런타임 옵션에 소유 컨테이너를
추가한다. FCEUX는 기존 캔버스를 계속 사용하고, 아케이드 어댑터만 해당
컨테이너 안에 EmulatorJS를 마운트한다. 어댑터는 다음 작업을 담당한다.

- ROM 바이트를 원래 드라이버명 ZIP으로 전달
- 선택된 `mame2003_plus` 또는 `fbneo` 코어 강제
- 시작, 일시정지, 재개, 리셋, 볼륨, 입력, 상태 저장·복원, 종료를
  `NesboxCore` 메서드로 변환
- 생성한 Blob URL, DOM, 이벤트, 오디오 노드를 종료 시 정리
- EmulatorJS 오류와 로딩 상태를 기존 상태 메시지로 변환

현재 `CoreRuntimeOptions`의 `canvas`와 `audioContext`는 FCEUX 호환을 위해
유지하고 `hostElement`를 추가한다. `EmulatorStage`는 캔버스와 빈 호스트를
모두 소유하되 선택한 코어에 맞는 한쪽만 표시한다. EmulatorJS는 자신의
캔버스와 오디오 컨텍스트를 호스트 안에서 만들고, 내장 툴바·키보드·게임패드
입력은 끈다. 화면 조작, 저장, 일시정지와 전체 화면은 기존 NESBOX UI가
계속 소유한다. 이렇게 하면 두 런타임의 DOM과 오디오 수명주기가 섞이지 않는다.

EmulatorJS의 문서화되지 않은 인스턴스 API가 필요한 부분은 어댑터 밖에서
직접 사용하지 않는다. 패키지 버전을 고정하고 가짜 런타임을 사용한 계약
테스트로 업그레이드 시 파손을 즉시 확인한다.

### 검토 후 제외: 별도 iframe 플레이어

라이선스와 런타임을 강하게 분리할 수 있지만, 키 설정, 전체 화면, 상태 저장,
오디오 상태와 라우트 수명주기를 `postMessage`로 중복 구현해야 한다. 현재
단일 플레이 화면과 설정 경험을 유지하려는 목표에 맞지 않는다.

### 검토 후 제외: 자체 Libretro WASM 프런트엔드

현재 `NesboxCore` 경계를 가장 순수하게 지킬 수 있지만 Libretro의 영상,
오디오, 입력, 파일 시스템, 코어 옵션, 상태 직렬화를 새로 구현해야 한다.
아카이브 이관보다 프런트엔드 개발이 주 작업이 되므로 이번 범위에서 제외한다.

## 라이선스와 제3자 고지

EmulatorJS 통합에 맞춰 NESBOX 애플리케이션 코드를 `GPL-3.0-only`로
전환한다. 다음을 함께 갱신한다.

- 루트 `LICENSE`를 GPL v3 전문으로 교체
- `package.json`의 라이선스를 `GPL-3.0-only`로 변경
- README의 라이선스 설명 갱신
- EmulatorJS와 각 코어의 원문 라이선스 및 출처를 제3자 고지 문서와 배포
  자산에 포함

MAME 2003-Plus와 FBNeo 코어는 각자의 비상업 라이선스를 그대로 따른다.
애플리케이션 코드의 GPL-3.0 표기와 코어의 라이선스를 혼동하지 않고, 코어는
별도 제3자 구성요소로 표시한다. 이 배포는 광고·판매·기부 유도 등 상업적
용도로 사용하지 않는 것을 전제로 한다.

## 데이터 가져오기

### 공통 원칙

새 스크립트는 아카이브 루트와 `NESBOX_DATA_DIR`을 명시적으로 입력받고 기본
동작은 dry-run으로 한다. 적용 모드에서는 먼저 SQLite 백업을 만든 뒤 임시
디렉터리에 ROM과 커버를 준비한다. 파일 준비와 검증이 모두 끝난 다음 DB
트랜잭션으로 게임을 등록하고 최종 경로로 이동한다. 실패하면 DB 트랜잭션을
롤백하고 이번 실행이 만든 임시 파일을 제거한다.

카탈로그의 기준 데이터는 아카이브의 `assets/game_details.json`이며 이미지
후보는 각 항목의 `download.image_files`와 `assets/game_image_mapping.json`을
교차 확인한다. 파일 시스템을 단순 순회해 제목이나 코어를 추측하지 않는다.
매니페스트의 `core`, `zip`, `name`, 실제 ZIP 경로 및 이미지 경로가 모두
일치해야 적용 후보가 된다. 원본 매니페스트와 ROM은 읽기 전용으로 취급한다.

DB 게임 ID는 현재 방식대로 `system + emulatorId + ROM SHA-1`을 사용한다.
스크립트는 DB ID뿐 아니라 등록된 모든 ROM 파일의 SHA-1도 비교해, 경로 또는
파일명이 달라도 같은 바이트이면 건너뛴다. dry-run과 적용 결과에는 추가,
건너뜀, 판본 추가, 오류 수와 항목 목록을 출력한다.

### NES 단계

- ZIP의 유일한 `.nes` 엔트리를 읽고 iNES 헤더를 다시 검증한다.
- 완전 중복 5개는 기존 행과 커버를 수정하지 않고 건너뛴다.
- 새로운 작품 21개와 다른 ROM 판본 7개, 총 28개를 FCEUX 프로필로 등록한다.
- 다른 판본은 내부 파일명에서 지역·번역 정보를 확실히 판별할 수 있으면
  `[한글판]`, `[일본판]`, `[미국판]`을 제목에 붙이고, 확실하지 않으면
  `[별도판]`을 붙인다.
- 아카이브의 한국어 카탈로그 제목을 표시 제목으로, ZIP 내부 ROM명을
  `originalTitle`로 사용한다.
- ROM은 해시 기반 `.nes` 파일로 데이터 디렉터리에 복사한다.
- 연결된 340×210 JPEG는 WebP로 변환해 커버로 저장한다.
- 현재 데이터 기준 적용 후 NES 수는 138개가 된다. 스크립트 재실행 시 0개가
  추가되어야 한다.

### 아케이드 단계

- `mame` 239개는 `mame2003-plus`, `fbn` 83개는 `fbneo`로 등록한다.
- 두 프로필 모두 `system`은 `arcade`로 저장하고 UI 카테고리는 `mame`으로
  계산한다.
- ZIP은 풀지 않고 원래 shortname을 `fileName`으로 보존한다. 저장 경로만
  해시 기반으로 만들며 EJS에는 원래 파일명을 함께 전달한다.
- ROM ZIP과 스크린샷은 운영 데이터 디렉터리로 복사한다. 원본 아카이브를
  이동하거나 수정하지 않는다.
- 한국어 카탈로그 제목을 표시 제목으로, shortname을 원제 식별자로 저장한다.
- 322개 모두 커버를 갖도록 연결된 이미지를 WebP로 변환한다.
- 현재 데이터 기준 NES 단계 이후 전체 게임 수는 460개가 된다. 아케이드
  수는 UI 기준 322개이며 재실행 시 중복이 생기지 않아야 한다.

현재 `original_title`은 박스아트 원제라는 좁은 설명을 갖고 있으므로 DB 컬럼을
늘리지 않고 의미를 `검색과 표시에 쓰는 원제 또는 소스 식별명`으로 일반화한다.
기존 NES 값은 그대로 유효하고, 신규 NES에는 ROM 내부명, 아케이드에는
shortname이 들어간다. API 타입 주석과 UI 표기도 이 의미에 맞춰 갱신한다.

## 라이브러리 카테고리와 검색

`CatalogCategory`를 `all | nes | mame`으로 정의한다. `nes`는 NES 시스템,
`mame`은 `arcade` 시스템의 MAME 2003-Plus 및 FBNeo 프로필을 포함한다.

기존 전체 게임/최근 플레이 보기는 유지하되, 별도의 카테고리 세그먼트
`ALL`, `NES`, `MAME`을 추가한다. 기본값은 `ALL`이다. 필터 순서는 다음과 같다.

1. 전체 또는 최근 플레이 원본 목록 선택
2. 선택한 카테고리 적용
3. 제목 및 원제 검색 적용
4. 선택한 정렬 적용

따라서 검색어가 남아 있는 상태에서 카테고리를 바꾸면 같은 검색어를 새
카테고리 안에서 다시 평가한다. 빈 결과 메시지는 선택한 카테고리와 검색어를
구분해 안내한다. 카테고리 버튼의 수는 검색어와 무관한 전체 라이브러리 수를
표시하고, 결과 영역에는 현재 표시 개수를 별도로 보여 준다.

게임 카드에는 사용자 카테고리 기준으로 `NES` 또는 `MAME`을 표시한다.
FBNeo 게임은 카드의 보조 코어 정보에서만 `FBNeo`로 구분한다. 기존 패미컴
카트리지 외형은 NES에 유지하고, 아케이드는 화면 비율 스크린샷이 자연스럽게
보이는 별도 아케이드 카드 외형을 사용한다.

## 조작 프로필

키 설정은 에뮬레이터 ID가 아니라 사용자에게 보이는 조작 프로필
`nes | mame` 단위로 저장한다. MAME 2003-Plus와 FBNeo는 같은 6버튼 물리
배치를 공유하되 어댑터가 각 코어가 기대하는 RetroPad 입력으로 변환한다.

키 값은 문자(`key`)가 아니라 물리 위치를 나타내는 `KeyboardEvent.code`로
저장한다. 따라서 한/영 상태와 무관하게 `KeyZ`, `KeyX` 위치가 유지되며 UI는
이를 `Z`, `X`처럼 사람이 읽는 라벨로 변환한다. 방향키도 `ArrowUp`과 같은
code를 쓴다.

기본 키는 다음과 같다.

| 기능 | NES | MAME |
| --- | --- | --- |
| 이동 | 방향키 | 방향키 |
| Select / Coin | Shift | Shift |
| Start | Enter | Enter |
| B / 버튼 1 | Z | Z |
| A / 버튼 2 | X | X |
| 버튼 3 | - | C |
| 버튼 4 | - | A |
| 버튼 5 | - | S |
| 버튼 6 | - | D |

MAME 논리 버튼 1~6과 RetroPad B/Y/A/X/L/R의 실제 대응은 코어 입력
디스크립터와 대표 6버튼 게임으로 검증해 어댑터 상수로 고정한다. 게임패드는
표준 버튼 0~5를 여섯 논리 버튼에 대응한다. 모바일 아케이드 터치 UI도 3×2
배열의 6버튼, Coin, Start를 제공한다. NES 터치 UI는 현재 A/B 및 A+B 구성을
유지한다.

## 시작 가이드와 도움말

키보드 안내를 데이터 기반 공용 컴포넌트로 만든다. 데스크톱 시작 가이드의
키보드 영역과 도움말 대화상자는 이 컴포넌트를 함께 사용한다.

- 탭은 `NES`, `MAME` 두 개이며 기본 탭은 NES다.
- NES 탭은 현재 방향키, Shift, Enter, Z/X 배치를 보여 준다.
- MAME 탭은 방향키, Coin, Start 및 Z/X/C·A/S/D 6버튼 배치를 보여 준다.
- 저장된 사용자 설정이 있으면 기본 키가 아니라 실제 현재 키를 표시한다.
- 탭은 키보드와 스크린리더로 선택할 수 있고 적절한 tablist/tab/tabpanel
  역할을 사용한다.
- 모바일 첫 방문 안내는 현재 터치 중심 설명을 유지하되 MAME 게임은 6버튼
  터치 패드를 사용한다는 문구를 추가한다.

## 설정의 키 커스터마이징

`UserSettings`에 `keyBindingsVersion: 1`과
`keyBindings: { nes: ..., mame: ... }`를 추가한다. 기존 설정에 해당 필드가
없거나 일부 값이 잘못된 경우 나머지 볼륨·배율·터치 설정은 보존하고 누락된
키만 기본값으로 채운다. 알 수 없는 기능 키는 버린다.

설정 시트에 `키보드` 구역과 NES/MAME 탭을 추가한다. 각 기능 행의 현재 키를
누르면 다음 키 입력을 기다리는 캡처 상태가 된다.

- Escape는 변경을 취소한다.
- 같은 프로필 안에서 이미 사용 중인 키를 지정하면 두 기능을 바꾸지 않고
  충돌 메시지를 표시한다.
- 방향, Start, Select/Coin 및 액션 버튼은 비워 둘 수 없다.
- 시스템 예약 조합과 단독 Control/Alt/Meta는 허용하지 않는다.
- 각 프로필에 `기본값 복원` 버튼을 제공하고 확인 후 해당 프로필만 초기화한다.
- 변경은 즉시 localStorage에 저장하고 다음 입력 이벤트부터 적용한다.
- 실행 중인 코어도 React가 새 키맵으로 이벤트를 해석하므로 게임을 다시
  로드하지 않고 변경이 반영된다.

키보드와 게임패드 이벤트의 단일 진입점은 NESBOX가 소유한다. 입력 필드, 키
캡처 UI 및 contenteditable에서는 게임 입력을 보내지 않는다. 게임이 활성화된
동안 지정된 키에만 `preventDefault`를 적용하고, blur·visibilitychange·코어
교체 시 눌린 버튼을 모두 해제해 고착 입력을 막는다. 아케이드 어댑터에서는
EmulatorJS의 자체 키보드·게임패드 감지와 내장 모바일 패드를 비활성화하고
NESBOX가 `setButton`으로 논리 버튼 상태를 전달한다.

## 오디오와 플레이 수명주기

FCEUX는 현재 공유 `audioSession`과 명시적 음소거 해제 정책을 그대로 사용한다.
EmulatorJS는 별도 오디오 컨텍스트를 소유하므로 아케이드 게임을 처음 열면
플레이 영역에 `게임 시작` 오버레이를 표시한다. 사용자의 클릭으로 런타임을
시작하고 오디오를 활성화한다. 자동 시작으로 브라우저 오디오 정책을 우회하지
않는다.

아케이드 런타임이 시작된 뒤 게임을 바꾸면 이전 인스턴스를 완전히 dispose한
후 새 코어를 만든다. MAME 2003-Plus와 FBNeo 상태는 서로 호환되지 않으며,
기존 저장 키 `gameId + emulatorId + slot`이 이 충돌을 방지한다.

상태 저장을 지원하지 않거나 직렬화에 실패하는 게임은 저장 버튼을 비활성화할
수 있도록 코어 오류를 명시적으로 반환한다. 실패를 성공으로 표시하지 않는다.

## 오류 처리와 복구

- 아카이브 파일, 이미지 또는 매니페스트가 없으면 해당 항목을 건너뛰지 않고
  전체 적용 전에 실패시켜 부분 카탈로그를 방지한다.
- ROM 해시와 파일 크기는 복사 후 다시 확인한다.
- 코어 자산 로딩 실패, ROM 세트 불일치 및 메모리 부족을 서로 다른 사용자
  메시지로 표시한다.
- 실패한 게임은 라이브러리에 남겨 두되 카드에 영구 오류 상태를 저장하지
  않는다. 코어 업데이트 후 다시 시도할 수 있어야 한다.
- 80MB급 FBNeo ROM은 진행률을 표시하고 중복 ArrayBuffer 복사를 최소화한다.
- ROM API는 기존 인증·오류 규칙을 유지하되 `Content-Length`를 제공한다.
  브라우저에서 한 번 받은 ArrayBuffer를 어댑터에 넘기고, 어댑터가 다시
  `fetch`하거나 base64 문자열로 복제하지 않는다.
- 배포 전 DB 백업 경로와 추가된 파일 목록을 기록한다. 롤백은 백업 DB 복원과
  이번 가져오기가 만든 해시 파일 삭제로 수행한다.

## 순차 구현과 완료 조건

### 1단계: NES 추가

- dry-run 보고서가 정확히 중복 5, 판본 7, 신규 21을 표시한다.
- 적용 후 기존 110개가 보존되고 NES 총 138개, 신규 커버 28개가 된다.
- 대표 기본 iNES 게임과 NES 2.0 헤더 게임을 FCEUX에서 실행한다.
- 재적용 결과 추가 0개다.

### 2단계: MAME 게임 추가

- 라이선스와 고지, 고정된 EmulatorJS 및 두 코어 자산을 추가한다.
- 아케이드 322개와 커버 322개를 등록한다.
- 고전 MAME, Neo Geo, CPS, FBNeo 대용량, 세로 화면 및 6버튼 게임을 포함한
  대표 세트를 실제 브라우저에서 실행한다.
- Coin, Start, 6버튼, 일시정지, 리셋, 상태 저장 가능 여부와 종료 시 자원
  정리를 확인한다.

### 3단계: 카테고리 필터

- ALL 460, NES 138, MAME 322가 현재 데이터 기준으로 표시된다.
- NES를 선택한 검색은 아케이드 제목을 반환하지 않고 반대도 동일하다.
- 최근 플레이 보기에서도 같은 카테고리 필터가 적용된다.

### 4단계: 시작 가이드 탭

- NES/MAME 탭, 기본 및 사용자 키 표시, 키보드 접근성을 확인한다.
- 도움말과 시작 가이드가 동일한 키 데이터를 표시한다.

### 5단계: 키 커스터마이징

- 기존 설정 마이그레이션, 정상 변경, 충돌 거부, 취소, 프로필별 초기화,
  새로고침 후 유지 및 실행 중 반영을 검증한다.
- NES 두 버튼과 MAME 여섯 버튼을 키보드·표준 게임패드·터치에서 확인한다.

### 전체 검증

- 가져오기 로직, 카테고리/검색, 설정 마이그레이션과 키맵은 단위 테스트로
  검증한다.
- EmulatorJS 어댑터는 가짜 런타임 계약 테스트와 실제 대표 ROM 브라우저
  테스트를 모두 둔다.
- `npm test`, `npm run typecheck`, `npm run build`가 통과해야 한다.
- 운영 DB 백업 후 배포하고 PM2 재시작 뒤 API 카운트, 커버 응답, NES와 MAME
  대표 게임 실행을 다시 확인한다.

## 구현자 재량

- 새 컴포넌트와 테스트 파일의 구체적인 파일 분할
- 설정 시트 안의 간격, 색상과 반응형 세부 치수
- 대표 ROM 테스트 세트의 정확한 항목 수. 단, 위에 열거한 하드웨어·입력
  범주는 모두 포함해야 한다.
- 가져오기 보고서의 표 형식과 로그 문구
